1. Project Title

Integrated BIST 100 Agentic Financial Analytics Harness: Sector Rotation, Technical Reversals, Fundamental Change,
Macro Context, News Intelligence and Backtest Verification

2. Project Overview

This project asks students to build an integrated educational financial-analysis system for a selected universe of BIST
100 stocks. The system does not consist of a single prediction model. Instead, it combines deterministic financial
tools, multiple evidence sources, historical verification, and a controlled AI-agent workflow.
Students investigate whether observable market patterns exist before a stock moves, whether lagging stocks within a
strong sector later catch up, whether weekday return patterns are stable, whether technical reversal events repeat,
and how quarterly financial changes are reflected in subsequent prices. The project also introduces macroeconomic
context, curated financial news, and speech-to-text summaries of instructor-approved public finance commentary.

 Core Design Principle

 LLM reasons and explains. Python tools calculate. The harness controls. Backtests verify. Evidence is logged. A human
 makes the final decision.

The system is strictly for educational and research purposes. It must not connect to a broker, send real orders,
manage real money, or present personalized investment advice.

3. Learning Objectives

· Build reproducible financial data pipelines for BIST 100 stocks and sector-level comparisons.
· Distinguish raw market data, deterministic calculations, model interpretation, and AI-generated explanation.
· Detect sector laggards and test whether relative underperformance is followed by statistically meaningful catch-

     up behavior.
· Test weekday and multi-day calendar patterns without assuming they are permanent.
· Measure repeated technical reversal behavior using Bollinger Bands, RSI extrema, Supertrend, KAMA and

     Ichimoku Cloud.
· Link quarterly financial-statement changes to post-disclosure price behavior using point-in-time data.
· Integrate USD/TRY, EUR/TRY, CBRT policy rates, Federal Reserve policy rates and TÜK inflation indicators.
· Integrate news and public expert commentary as timestamped contextual evidence rather than as unverified

     financial facts.
· Design an MCP-based agent architecture with constrained tools, state, evidence, memory, verification and human

     review.
· Understand why backtest performance, prediction accuracy and LLM confidence are different concepts.

4. Financial Problem Definition

The system should answer research questions rather than simply output a BUY or SELL label. A useful output is an
evidence-backed analytical state such as 'sector laggard with improving fundamentals', 'historically repeated lower-
Bollinger reversal', or 'weekday pattern not statistically stable'.
The four mandatory research scenarios are:
· Sector Relative-Value / Catch-Up Scenario
· Weekday and Multi-Day Pattern Scenario
· Technical Reversal Event Scenario
· Quarterly Fundamental Change and Price-Reaction Scenario

8. Technical Reversal Event Framework

Students should treat a technical event as a timestamped research event. The system records the event, the market
state at that time, and the forward return after fixed horizons.

 Example event record
 Ticker: ASELS
 Event: Bollinger Lower Band Touch
 Event Date: t
 RSI State: Local Low
 Supertrend State: Bearish
 KAMA Slope: Flattening
 Ichimoku State: Below Cloud
 Volume Regime: High
 Forward Return Horizons: 1d, 3d, 5d, 10d
 Reversal Strength: measured after the event

Mandatory event families:

· Lower Bollinger Band touch followed by an upward reversal.
· Middle Bollinger Band test followed by continuation or rejection.
· Upper Bollinger Band touch followed by a downward reversal.
· RSI local trough and local peak events; optionally divergence candidates.
· Supertrend direction flips and subsequent returns.
· KAMA slope changes, KAMA-price crosses and adaptive trend persistence.
· Ichimoku cloud breakout, cloud rejection and return into the cloud.
· Support/resistance touches with reversal-strength measurement.

10. Feature Engineering

· Daily and weekly returns, rolling volatility, ATR and volume z-scores.
· Relative return versus XU100, sector benchmark and peer median.
· Sector lag score: stock return minus sector-median return over several windows.
· Distance from Bollinger bands, KAMA, support/resistance and Ichimoku cloud boundaries.
· Event-count features: how many similar reversals occurred in the historical window.
· Reversal-strength features over 1, 3, 5 and 10 trading days.
· Weekday and multi-day sequence labels (e.g., Mon-Tue-Wed down, Thu-Fri up).
· Quarterly revenue, EBITDA, net profit, margin, ROE and leverage changes.
· Post-disclosure abnormal return relative to sector and XU100.
· Macro changes: USD/TRY, EUR/TRY, TCMB rate, Fed rate, monthly/annual CPI.
· News event tags and speech-intelligence topic/stance tags with timestamps.

11. Mandatory Research Scenario 1 -- Sector Laggard / Catch-Up

Opportunity

Goal: identify stocks that are materially lagging their own sector while the sector is strong, then test whether selected
laggards historically tend to catch up before an obvious price surge occurs.

 Illustrative Scenario -- Banking Sector

 Assume AKBNK, GARAN, ISCTR and YKBNK form the peer group. Over the latest 20 trading days, the sector median return
 is +12%. Three banks gained roughly +11% to +16%, while one bank gained only +3%. The lagging bank is not
 automatically a BUY. The harness asks whether (a) fundamentals are deteriorating, (b) technical trend is stabilizing, (c)
 relative weakness has historically mean-reverted, and (d) macro conditions explain the lag. If fundamentals are stable and
 price begins to recover above KAMA / Supertrend while the sector remains strong, the system may label it
 'POTENTIAL_CATCH_UP_CANDIDATE' for backtest verification.

Required analysis:
· Build peer groups by sector.
· Calculate stock return minus sector median/sector index return over several windows.
· Rank laggards and leaders inside each sector.
· Measure whether laggards subsequently outperform peers over 5/10/20 trading days.
· Separate structural laggards from temporary laggards using fundamental and macro evidence.
· Backtest the rule across sectors and periods before presenting any conclusion.
· Report false positives: lagging stocks that continued to underperform.

12. Mandatory Research Scenario 2 -- Weekday and Multi-Day Patterns

Goal: test whether individual stocks or sectors exhibit recurring day-of-week or multi-day sequences, while
recognizing that apparent patterns may disappear out of sample.
 Illustrative Scenario -- THYAO

 Suppose historical data suggests a sequence in which Monday, Tuesday and Wednesday are more frequently negative,
 followed by positive Thursday and Friday returns. Students must not assume this is tradable. They should count
 occurrences, compare average and median returns, test different market regimes, compare against random or
 unconditional returns, include transaction costs, and evaluate whether the pattern remains in later unseen periods. A
 second stock may show the opposite pattern.

Examples of patterns to test:
· Monday weakness followed by Friday strength.
· Three consecutive down days followed by a two-day rebound.
· Post-large-down-day mean reversion.
· End-of-week continuation versus reversal.
· Patterns conditional on XU100 direction, sector direction or macro-event weeks.
Students should explicitly discuss multiple-testing risk. Searching hundreds of combinations can create false patterns
by chance.

13. Mandatory Research Scenario 3 -- Technical Reversal Patterns

 Illustrative Scenario -- ASELS

 The system finds 24 historical lower-Bollinger touches. In 15 cases, price moved higher within the next five trading days.
 When the lower-band touch occurred together with an RSI local trough, rising volume and a flattening KAMA, the five-day
 reversal was historically stronger. However, when price remained below a bearish Supertrend and below the Ichimoku
 cloud, several signals failed. The harness therefore compares single-indicator events against combined-event conditions.

Students should calculate:
· Number of lower-band, middle-band and upper-band touches.
· Bounce/failure count from each band.
· Average/median reversal strength after each event.
· RSI trough/peak behavior and optional divergence candidates.
· Supertrend flip follow-through.
· KAMA-cross and KAMA-slope behavior.
· Ichimoku cloud breakout/rejection statistics.
· Results by market regime: rising XU100, falling XU100, high-volatility and low-volatility periods.

14. Mandatory Research Scenario 4 -- Quarterly Fundamentals and Price
Reaction

Goal: connect quarterly changes in company financials to price behavior after the information becomes public.
 Illustrative Scenario -- TUPRS

 Assume a quarter shows improving revenue, EBITDA margin and operating cash flow, while Net Debt/EBITDA declines.
 The system aligns those values with the public disclosure timestamp. It then measures the stock's 1-day, 5-day and 20-
 day returns after disclosure, and also calculates abnormal return versus both XU100 and a sector peer basket. The same
 procedure is repeated across many quarters. The research question is not 'good earnings = price rises'; it is whether
 specific changes were historically associated with different price reactions.
The system should support:

· Quarter-over-quarter and year-over-year changes in revenue, EBITDA and net profit.
· Changes in ROE, margins, liquidity and leverage.
· Valuation changes before and after the reporting period.
· Disclosure-date alignment to avoid look-ahead bias.
· Post-disclosure returns and abnormal returns versus sector/XU100.
· Comparison of positive fundamental surprises with weak technical states, and vice versa.
· Sector-specific metrics where appropriate; bank analysis should not blindly use industrial-company ratios.

16. Financial News and Speech Intelligence Layer

The system may enrich structured data with unstructured context from Bloomberg or other legally accessible high-
quality financial news feeds and from selected public finance videos.

News pipeline:

· Collect legally accessible headline/article metadata with publication timestamp.
· Tag company, sector and macro topics.
· Extract event categories such as earnings, regulation, FX, rates, commodity shock, contract award or geopolitical

     risk.
· Optionally calculate a simple sentiment/stance label, but preserve the original source and timestamp.
· Never replace numerical market/fundamental data with a language-model guess.

Speech-to-text pipeline:

· Use instructor-approved public videos from reputable finance educators/practitioners and official financial
     channels.

· Examples may include public valuation teaching by Aswath Damodaran and public macro/investment
     commentary from well-known practitioners; the instructor-approved list should be fixed before experiments.

· Convert selected video segments to text, preserving video URL, speaker/channel, publication time and transcript
     time range.

· Extract topics, claims, stance and uncertainty.
· Numerical claims in commentary must be checked against deterministic data tools before entering the

     committed evidence set.
· Expert opinion is contextual evidence, not ground truth.

18. Backtesting and Verification Harness

Every strategy or discovered pattern should be historically verified before the system presents a strong conclusion.

· Use signal shifting so decisions at time t cannot use the close or information from t+1.
· Use financial-statement publication dates, not only quarter-end dates.
· Compare against Buy-and-Hold, XU100 and where possible a sector benchmark.
· Report cumulative return, Sharpe ratio, maximum drawdown, win rate and benchmark difference.
· Include transaction-cost and simple slippage assumptions.
· Use train/validation/test or rolling walk-forward periods for data-mined rules.
· Report the number of signals; a high return from very few events should be flagged.
· Use regime breakdowns and out-of-sample testing for weekday/pattern discoveries.

26. Data Quality and Risk Gate

Hard blocks:
· Future financial-statement information enters an earlier historical date.
· Look-ahead bias in indicator/signal construction.
· Wrong ticker or broken price history.
· Critical period mismatch between price and financial data.
· Backtest uses information unavailable at decision time.
Soft warnings:
· Macro series unavailable for a limited interval.
· News coverage is sparse.
· Video transcript quality is low.
· Small number of historical technical events.
· Sector peer group is temporarily too small.

 Possible gate outputs
 PASS
 PASS_WITH_WARNINGS
 INVESTIGATE
 ANALYSIS_UNSAFE
 HARD_BLOCK

 2. Market tool loads OHLCV and XU100.

 4. Sector tool ranks each stock versus its peers.

 6. Fundamental tool loads only financial data that was public by the analysis date.
 7. Macro tool loads FX, CBRT/Fed rate context and TÜK inflation.

 9. Evidence Builder separates observed context from committed evidence.
 10. Strategy Agent creates several candidate rule sets.

 14. Human reviewer accepts, modifies or rejects it.

34. Methodology

1. Freeze the 30-stock universe and sector map for the experiment period.
2. Collect and version market, fundamental and macro datasets.
3. Create point-in-time publication calendars for financial and macro data.
4. Engineer technical, relative-value, fundamental and contextual features.
5. Define event-based research questions before looking at outcomes where possible.
6. Run mandatory sector, calendar, reversal and fundamental-reaction scenarios.
7. Develop several rule-based strategy variants.
8. Backtest with proper signal timing, benchmark comparison, costs and out-of-sample checks.
9. Integrate tools into MCP and implement the stateful harness.
10. Add evidence bundles, memory, quality gates and human review.
11. Run harness experiments A­E and compare reproducibility/safety.
12. Document limitations and cases where the system returns INVESTIGATE or ANALYSIS_UNSAFE.

38. Final Learning Outcomes

At the end of the project, students should understand that a financial AI system is not valuable because it can produce
a confident sentence. It is valuable when its data are correctly timed, its calculations are reproducible, its actions are
constrained, its evidence is inspectable, its historical claims are verified, and its conclusions can be challenged by a
human.

 Key Final Principle

 The purpose of the AI agent is not to invent or predict financial facts. Its role is to orchestrate deterministic analytical
 tools, manage evidence and state, enforce a controlled analysis workflow, and explain reproducible results.

Students should be able to explain the following distinctions:

· Prediction  profitable strategy
· Correlation  causation
· Backtest  future guarantee
· Historical evidence  investment advice
· LLM confidence  statistical probability
· Fundamental strength  guaranteed stock-price increase
· Expert commentary  verified fact
